Damir Hotel — What's Blocking Sellable Shape?

5 advisors · 5 peer reviews · Chairman synthesis · June 15, 2026
Chairman's Verdict

The full synthesis — read this first

Where the Council Agrees
No prices shown anywhere — #1 conversion killer (unanimous)

A guest who can't see a price leaves immediately to Booking.com and books there, paying OTA commission. The site is actively funding the middleman. Even "from $X/night" hardcoded is infinitely better than nothing.

No WhatsApp button — dealbreaker for this market (unanimous)

Uzbekistan runs on WhatsApp. Telegram alone misses half the regional audience. A floating WhatsApp button (wa.me link) is the single highest-ROI change on the site and it's one anchor tag.

Google Apps Script URL exposed in hotel.js (4/5 advisors)

The form endpoint is in a public JS file, unauthenticated. One scraped cache away from becoming a spam cannon that exhausts the hotel's Gmail quota. This is an operational risk, not a UX issue.

Hardcoded review stats will become a credibility time bomb (4/5 advisors)

When the real Booking.com score drifts, the site shows stale numbers. A guest who cross-references will notice. Fix: add "Source: Booking.com ↗" with an inline link to the property page.

No JSON-LD structured data (3/5 advisors)

Google won't show rich results for "hotel in Nukus." Hotel schema (name, address, telephone, priceRange, geo) is ~20 lines and a one-time fix on index.html.

Where the Council Clashes
Is the inquiry form the wrong tool entirely?

The First Principles Thinker argues Central Asian guests book via WhatsApp DM — the form is solving the wrong problem. The Executor says fix the form's blockers and it works fine. Resolution: both coexist. International tourists (the Savitsky Museum draws Western visitors) prefer email forms. Local/regional guests prefer WhatsApp. WhatsApp goes first, above the fold, on every page. The form becomes the secondary option.

Content strategy now vs. later?

The Expansionist wants a blog, local SEO content, and editorial depth targeting "hotel Nukus" in three languages — the multilingual infrastructure already exists. Every peer reviewer called this premature. Fix the conversion basics first. The SEO opportunity is real but it's a post-launch concern, not a blocker.

Blind Spots the Council Caught (emerged in peer review)
Mobile performance — the problem that kills everything else first

A dark-luxury site with heavy hero images on a market where many users are on 3G/4G mobile means the page may not finish loading before the guest abandons. No advisor mentioned Core Web Vitals, image compression, or LCP. Slow load kills conversion before any other issue matters.

privacy.html is untracked in git — may not survive deployment

The file exists locally but hasn't been committed. Additionally, the inquiry form collects names and email addresses with no consent checkbox — legal exposure that's trivially fixable: one checkbox + one sentence linking to the privacy policy.

Multilingual form flow is untested as a conversion path

The i18n infrastructure exists but whether form error states, validation messages, placeholder text, and the post-submit confirmation are translated into UZ and RU is unverified. An Uzbek-speaking guest who gets English validation errors has a broken experience. This is a launch blocker.

HTTPS enforcement unverified

The form collects personal guest data (name, email, phone). If the site can be served over HTTP, form submissions travel in plaintext. Must be confirmed before launch.

⚠️ Council error, corrected: Three peer reviewers flagged "the form auto-reply is missing." It's actually already implemented in form-endpoint.gs — MailApp.sendEmail() sends a confirmation to the guest on submit. The real gap is the in-page confirmation message doesn't state a reply timeframe. Fix the copy ("we'll respond within 4 hours"), not the code.
The Recommendation — priority order
  • 1
    Blocker Add prices to rooms page

    Call the owner, get a "from $X/night" figure for each room category. Hardcode it in rooms.html and room.html. No live calendar needed — static text converts far better than nothing.

  • 2
    Blocker Add WhatsApp floating button to every page

    One <a href="https://wa.me/[number]"> tag, fixed bottom-right, wired in site.js alongside the existing Telegram link. Highest-ROI change on the site.

  • 3
    Blocker Harden the Apps Script endpoint

    Add CORS/Referrer validation in doPost() to reject requests not from the site domain. Add rate-limiting via PropertiesService. Do this before the site goes public.

  • 4
    Blocker Commit privacy.html + add consent checkbox to forms

    git add and commit privacy.html. Add a checkbox to the inquiry form: "I agree to processing of my personal data per the Privacy Policy." Legal requirement.

  • 5
    Should Fix Add reply ETA to the post-submit confirmation message

    The auto-reply email already fires. The in-page confirmation just needs copy like "We'll get back to you within 4 hours" so guests don't feel they shouted into a void.

  • 6
    Should Fix Attribute the stats strip to Booking.com

    Add "Source: Booking.com ↗" as an inline link below the 8.2 / 9.3 / 155 figures, or link each to the hotel's Booking.com page. Unattributed numbers feel fabricated.

  • 7
    Should Fix Add JSON-LD Hotel schema to index.html

    ~20 lines: name, address (with Latin transliteration alongside Cyrillic), telephone, priceRange, geo coordinates. Makes Google show rich results for "hotel in Nukus."

  • 8
    Should Fix Audit multilingual form states in UZ and RU

    Switch the site to UZ, submit with an invalid email, then empty required fields, then successfully. Every error message, label, and confirmation must be translated. Fix any English strings that leak through.

  • 9
    Should Fix Optimize hero images for mobile + verify HTTPS

    Compress and serve responsive images. Confirm loading="lazy" on all below-fold images. Run Lighthouse on throttled mobile. Get LCP under 3s. Confirm the site enforces HTTPS before form data can be submitted over HTTP.

  • 10
    Polish Add geographic anchor and surroundings context to homepage

    "2–3 hours from Tashkent by air," "walking distance from the Savitsky Museum," "Nukus city centre." International guests don't know where Nukus is. This is the single biggest selling point for cultural tourists — lean into it.

Everything else is dev work you can do alone in an afternoon. Prices require the owner. That conversation also confirms they're ready to go live. Start there — it unblocks everything.
